That query is VERY simple, just a basic write. But it's a lot of them, the disk can't keep up with the transaction commits to the WAL. If we look at that postgres box in Signoz we see it queuing up writes REALLY bad (that number should be 0 -always-, maybe 1 or 2, but here it hits like 20)

Postgres' staging disk is a logical volume that's striped across four disks (everything that says lvm here):

 Again, these are very basic commits. I think our indexing bottleneck here is actually postgres' disk, and the worst thing is I suspect we're slowing down everyone on that staging postgres while we're doing those inserts :(
 
 To fix that performance problem I think we'd need to be able to move the WAL to fast local disk, but I don't think we have any available - all the VM disk comes from the SAN.
