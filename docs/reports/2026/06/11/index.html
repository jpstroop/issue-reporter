ruby.hash_new_capa() creates a new Ruby hash with enough memory allocated to accommodate the specified number of entries. I have not actually benchmarked this. Notes: 1. The top-level Podman container (running the CircleCI execution environment) is spawned by Nomad as an unprivileged user. When it attempts to launch the inner container, it needs to slice up its given UIDs via /etc/subuid and /etc/subgid. If the top-level container was not allocated a subordinate range by the underlying Nomad host, it throws a sys-cap error or crashes instantly.

a. Nomad client needs to explicitly pass the /etc/subuid and /etc/subgid configuration allocations from the bare-metal server down into the first-tier CircleCI execution container
b. ensure Podman is set up to utilize vfs or fuse-overlayfs rather than trying to call standard host kernel drivers.

2. Tests can Spike cpu usage to 250% on initianalization. The unprivileged nested Podman layers see the entire underlying Nomad host hardware (e.g., a 32-core or 64-core bare-metal machine). If the runner job tries to immediately spawn 64 parallel threads, it will briefly hit 250%+ CPU utilization right at initialization ref #7206

a. Enforce hard resource limits to prevent spawning dozens of parallel threads instantly pushes the environment over the allocation threshold

3. Make logging easier to find ref #7211

a. Send Nomad logs to signoz
