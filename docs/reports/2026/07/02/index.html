Final summary of steps from Claude:

Summary Migrates spec/features/requests/formspec.rb off VCR entirely. Every HTTP request is now explicitly stubbed with the existing WebMock helpers (stubsingleholdinglocation, stubavailabilitybyholdingid, stubcatalograw), so unstubbed requests fail loudly instead of being silently served by the cassette. The 1.4 MB form_features.yml cassette is deleted (nothing else referenced it); VCR config is untouched for other specs.

How the stubs were derived Rather than guessing from failure output, a per-example HTTP request inventory was logged while the suite was still green under VCR (via a temporary WebMock.after_request hook). Each request VCR was still serving was mapped to a helper call in the example that makes it, and missing fixtures were extracted verbatim from the cassette's recorded response bodies.

Changes Remove vcr: { cassettename: 'formfeatures', record: :none } from the describe block; add ~155 stub helper calls across 66 examples Extract 76 new fixtures from the cassette (availability, holding-location, and catalog /raw bodies) Update 13 existing fixtures that had drifted from the recorded data — delivery locations and item barcodes no longer matched, which VCR's playback precedence over local stubs had been masking Stub two bibdata availability endpoints the cassette served as errors (a 400 and a 504) inline, since the helpers only produce 200s Replace an Illiad transaction stub whose .with body matcher was copied from a different bib and never matched; the cassette's 401 had been masking it, so the stub now returns the 401 the tests actually exercised Delete spec/cassettes/formfeatures.yml Testing Baseline before changes: 72 examples, 0 failures (with VCR) Final state (no VCR metadata, cassette deleted): 72 examples, 0 failures Sibling specs sharing the updated fixtures (marquand feature, scsb model, requests helper, request mailer, request options): all pass except marquandspec.rb:69, which fails identically on clean main — it's a pre-existing isolation flake where the first CAS-authenticated example in a fresh rspec process loses its login_as session and renders the sign-in page.
